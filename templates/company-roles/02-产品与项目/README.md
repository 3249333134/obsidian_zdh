# 产品／项目知识库

## 分类
- 用户场景与研究
- 需求池与优先级
- 需求规格与验收
- 路线图与里程碑
- 项目风险与变更
- 协作与交付
- 产品指标与实验
- 项目复盘

## 整理规则
按用户问题、需求、方案、验收、交付和反馈串联资料。访谈原话、需求假设、已确认需求和已上线能力分开记录；不把客户愿望写为承诺。优先级说明价值、成本、依赖及决定依据。变更保留原方案、影响与批准记录。计划完成不代表用户价值已验证，验收必须有证据。没有明确证据时不补造用户量、排期或负责人，AI建议不得自动变成正式需求或任务。

## 常用问题
- 有哪些已验证的用户问题，对应哪些需求与证据？
- 已发布方案为什么采用当前设计，放弃了哪些选项？
- 哪些需求有清晰的范围、不做项和验收标准？
- 历史变更对里程碑和风险产生了什么影响？
- 相似项目的交付与复盘有哪些可复用经验？
- 哪些产品结论来自实验，哪些仍是假设？

## 可手动创建的个人计划
- 整理需求证据与范围边界
- 完成需求方案和验收标准评审
- 核对项目里程碑、风险与依赖
- 完成交付验收与项目复盘
